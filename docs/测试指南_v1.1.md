# AIsci 核心功能测试指南 (2026-01-31)

本指南旨在指导开发人员和测试人员对 AIsci 系统进行完整的手动和自动化测试。

## 1. 自动化测试 (后端核心)

后端核心逻辑已建立单元测试套件，涵盖了结构化分析、病例管理、文档生成等。

### 运行方式
```powershell
# 在项目根目录下运行所有测试
python src/tests/run_tests.py

# 运行特定模块测试
python src/tests/run_tests.py core        # 核心逻辑
python src/tests/run_tests.py nlp         # NLP 处理
python src/tests/run_tests.py integration  # 集成流程
```

### 验证标准
- [ ] 17/17 个核心单元测试全部通过 (Pass)。
- [ ] 测试生成的临时文件 (`test_cases/`, `test_exports/`) 在测试结束后自动清理。

## 2. Web 端手动功能测试 (黑盒测试)

针对近期优化的“完善临床建议”相关功能，请按照以下步骤进行手动验证。

### 准备工作
1. 启动后端：`python src/api_server.py`
2. 启动 cpolar (如需公网访问)：`cpolar http 5000`
3. 访问地址：`http://localhost:5000` 或 cpolar 生成的公网 URL。

### 场景 A：完整接诊流程与流式分析
1. **录音测试**：点击“麦克风”按钮，模拟一段医生与患者的对话。
   - *预期*：左侧“原始转录”区域实时显示语音识别结果，识别应准确无误。
2. **自动分析**：录音停止后，系统应自动触发“结构化分析”。
   - *预期*：状态栏显示“正在进行AI结构化分析...”，右侧区域开始流式显示（主诉、现病史等要素逐一出现）。
3. **性能验证**：观察从录音结束到完整报告生成的时间。
   - *预期*：流式响应应在 1-2 秒内开始反馈，总耗时应显著低于非流式版本。

### 场景 B：病例保存与历史回溯
1. **保存功能**：点击“保存病例”按钮。
   - *预期*：按钮变为绿色并提示“保存成功”，侧边栏历史记录列表立即更新，出现刚才录入的病例。
2. **加载功能**：在侧边栏点击刚才保存的病例。
   - *预期*：中间和右侧区域的数据立即填充，包括患者信息、结构化要素、AI 建议和完整报告。

### 场景 C：导出与分享
1. **复制功能**：点击“复制结构化数据”按钮。
   - *预期*：按钮有点击反馈（变色/勾号），粘贴到记事本中应包含患者信息、各要素章节、AI 建议和完整报告。
2. **Word 导出**：点击 “Word” 导出按钮。
   - *预期*：浏览器立即弹出文件下载对话框，下载的文件名为 `[CaseID]_[姓名]_病历.docx`，打开后格式整齐。
3. **PDF 导出**：点击 “PDF” 导出按钮。
   - *预期*：浏览器立即下载 PDF 文件，打开后应支持中文字符显示，包含医院抬头和医生签名栏。

## 3. 边界与异常测试

| 测试项 | 操作步骤 | 预期结果 |
| :--- | :--- | :--- |
| **空内容分析** | 在没有任何转录文本时点击“结构化分析” | 弹出 Toast 提示“暂无有效转录内容” |
| **断网重连** | 录音过程中人为切断网络 | WebSocket 报错并提示“通讯链路异常” |
| **超长对话** | 输入或录制超过 2000 字的对话 | 系统能正常处理，不应出现崩溃，但分析时间可能略微增加 |
| **隐私检查** | 检查保存的 JSON 文件 (`/cases` 目录) | 敏感数据应按预期存储，文件编码为 UTF-8 |
